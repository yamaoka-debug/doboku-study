# 土木ノート

土木施工管理の問題を一問ずつ解き、採点と解説確認、誤答復習ができるブラウザ学習ツールです。初期収録は、指定サイトに掲載されている平成30年度〜令和8年度の1級土木・第一次検定（旧学科試験）9年分879問です。問題A/Bと問題番号で原本PDF・正答表を対応づけています。`demo.json` の3問はオリジナルの動作確認用例題です。

## 起動・テスト

Node.js 18以上とPython 3を使用します。外部パッケージのインストールは不要です。

```sh
cd /workspace/doboku-study
npm start
```

サーバーのポートは8000です。検証は `npm test`。`index.html` を直接開かず、HTTPサーバー経由で利用してください。

## 問題と解答の対応

画面の「取り込み用テンプレートを保存」から形式を取得できます。`questions` と `answers` の各行の `year`・`exam`・`number` を文字列で揃えます。正答の `answer` は1始まりの選択肢番号です。年度、第一次・第二次などの試験区分、午前・午後などを正確に区別してください。

同じ識別情報の重複、正答欠落、余剰解答、選択肢範囲外の正答は取り込みを拒否します。問題と正答を一体にしたJSON配列も取り込めます。取り込みは現在の問題集を置き換えます。

学習履歴はブラウザのlocalStorageに保存します。「学習データを保存」で問題集と履歴をJSONに書き出し、そのファイルを取り込むと復元できます。別ブラウザや保存領域の削除には自動追従しません。

## 指定サイトについて

https://dobokujira.com/1doboku-pastproblems/

接続して各年度の問題PDFと正答表を確認済みです。問題文や図表は再配布せず、掲載元のPDFを該当ページから表示します。原本の閲覧にはネット接続が必要です。PDFを埋め込み表示できないブラウザでは「原本のPDFを開く」を使用し、表示された問題番号を解答してください。PDFによっては同じページに複数の問題があります。

- 平成30年度〜令和5年度：各96問（A61問、B35問）
- 令和6年度〜令和8年度：各101問（A66問、B35問）
- 正答表は答えの番号のみを掲載しています。解説は付属しません。
- 平成20〜29年度の正答表は画像形式で、読み取りを確認できていないため採点データは未収録です。全年度の原本は掲載サイトから閲覧できます。
- 第二次検定は一覧に正答表がないため、自動採点対象外です。
- 本ツールは学習用です。年度ごとの必須・選択問題数を再現した模擬試験ではありません。

既存の問題集・履歴が保存されているブラウザでは、それを保持して起動します。「収録過去問を追加する（履歴を保持）」で過去問を追加してください。同じ識別キーの収録問題は最新版に更新し、履歴は保持します。

## データ作成・検証

`scripts/source-index.json` に掲載サイトから取得した各年度の原本URL、`scripts/verification.json` に取得PDFのSHA-256と照合件数を記録しています。データ作成はPythonのpymupdfとシステムのpdftotextを使用。アプリ実行にはこれらは不要です。

```sh
python3 scripts/build-past-exams.py --cache /path/to/pdf-cache
```

キャッシュは一覧順に `{年度インデックス}-{資料インデックス}.pdf`（資料0=A、1=B、2=正答）とします。正答表の連番・範囲と、全問題PDFの番号・掲載ページを検証し、不一致時は停止します。令和3年度は画像形式の正答表を目視照合して転記した値を使用しています。原本PDFはリポジトリに含めません。

## スマホでインターネット経由で利用する

スマホでの利用には、アプリをHTTPSの静的サイトとして公開する必要があります。クラウド開発環境の起動や公開は、アプリのWeb公開とは別の操作です。

### 公開用ファイル

`npm run build` で `dist/` と `doboku-study-mobile.zip` を生成します。公開対象は `dist/` の中身だけです。ZIPに原本PDF・Gitメタデータ・開発スクリプト・ブラウザの個人履歴は含みません。ZIPを展開したフォルダをNetlifyなどの静的サイトホスティングにアップロードすると、サービスがHTTPSの公開URLを発行します。

### このリポジトリのGitHub Pagesで公開する場合

1. 作成したファイルを `yamaoka-debug/doboku-study` の既定ブランチに反映します。
2. GitHubのリポジトリの **Settings → Pages → Source** を **GitHub Actions** にします。
3. **Actions → Publish study app to GitHub Pages → Run workflow** を実行します。
4. 成功した実行の `github-pages` 環境に表示されるURLをスマホで開きます。

ワークフローは手動実行のみです。用意したファイルだけではGitHubへの反映やWeb公開は実行されません。GitHub APIで公開設定を確認するには `api.github.com` への通信と、そのリポジトリの管理・公開権限が必要です。

### ホーム画面に追加

- iPhone：公開URLをSafariで開き、共有メニューの「ホーム画面に追加」を選びます。
- Android：公開URLをChromeで開き、メニューの「ホーム画面に追加」またはアプリ内の追加ボタンを使います。

原本PDFは別画面で開いて読み、このアプリに戻って選択肢を解答してください。同じ画面に表示するボタンもあります。ホーム画面に追加したアプリと通常のブラウザは、端末によって保存領域が別になることがあります。移行前に「学習データを保存」でバックアップし、必要に応じて復元してください。

初回に通信中に開いて準備が完了すると、アプリ画面・正答データをオフラインでも開けます。原本PDFはキャッシュしないため、閲覧には通信が必要です。履歴は端末ごとの保存で、自動同期はありません。

### モバイル検証

`npm test` に加えて、PlaywrightとChromiumがある環境では `npm run build` の後に `python3 tests/mobile-smoke.py` を実行できます。タッチ操作、320〜430pxの画面幅、原本リンク、ホーム画面用アイコン、サブディレクトリでのService Worker、通信遮断後の起動と履歴保存を検証します。iPhone/Android実機でのホーム画面インストールは別途確認が必要です。
